# Спецификация панели ассистента `Гоша`

## Назначение

Этот документ фиксирует целевую структуру собственной панели управления ассистентом в `GOSHA_PLATFORM`.

## Статус реализации на текущий момент

- Первая версия панели уже реализована в коде и выведена в операторский интерфейс.
- Уже есть:
  - составные профили ассистента;
  - профили голоса;
  - профили памяти;
  - наборы `MCP`;
  - профили экрана;
  - профили пробуждения;
  - профили базы знаний как отложенный серверный слой;
  - привязка составного профиля к роботу;
  - внутренний `OpenAI`-совместимый прокси панели к `gosha-agent-gateway`.
- Этот документ остаётся спецификацией второй и следующих очередей:
  - доведение применения экранных и wake-профилей до прошивки;
  - живая база знаний и индексация;
  - улучшение голосовых профилей;
  - дальнейшая увязка с `GOSHA_FIRMWARE`.
- На текущей живой точке уже есть рабочий русский набор голосов:
  - `voice-ru-default` — Светлана, основной женский голос
  - `voice-ru-man` — Дмитрий, взрослый мужской голос
  - `voice-ru-kid-girl` — детский пресет на базе Светланы
  - `voice-ru-kid-boy` — детский пресет на базе Дмитрия
- Важно: два детских варианта в первой версии — это не отдельные нативные детские голоса поставщика, а детские пресеты на базе русских голосов `Microsoft Edge` через повышенные параметры скорости и высоты голоса.

Панель должна заменить зависимость от внешней страницы `xiaozhi.me` для настройки:

- роли ассистента;
- языка диалога;
- голоса;
- памяти;
- модели;
- `MCP`-сервисов;
- базы знаний;
- экранного поведения робота;
- имени пробуждения `Гоша`.

## Что должно появиться в `Гоша`

Панель `Гоша` должна быть масштабируемой и не завязанной на одного робота, один голос или одного поставщика ИИ.

Обязательные разделы первой версии:

1. `Ассистенты`
2. `Голоса`
3. `Экран и лица`
4. `Пробуждение`
5. `Память`
6. `Инструменты MCP`
7. `База знаний`
8. `Привязка профиля к роботу`

## Раздел `Ассистенты`

Должен поддерживать:

- имя ассистента;
- краткое описание роли;
- полный системный промпт;
- шаблон роли;
- язык диалога;
- модель;
- профиль поставщика ИИ через `gosha-agent-gateway`;
- флаг профиля по умолчанию;
- статус доступности профиля.

## Раздел `Голоса`

Должен поддерживать:

- выбор голоса;
- метку голоса для оператора;
- язык голоса;
- тип голоса:
  - взрослый;
  - детский;
  - нейтральный;
- скорость речи;
- высоту голоса;
- тестовое прослушивание;
- возможность в будущем добавить клон голоса как отдельный этап.

Первая версия должна опираться на OpenAI-совместимые и совместимые серверные `TTS`-профили без жёсткой привязки к одному поставщику.

На текущем живом контуре уже подтверждено:

- серверный `EdgeTTS` умеет применять:
  - имя голоса
  - скорость речи
  - высоту голоса
- панель и слой хранения уже умеют сохранять эти параметры в `voice_profile`
- серверная конфигурация уже получает эти параметры при переустановке контура через `ops/install_server.sh`

Текущее ограничение первой живой версии:

- в совместимом голосовом `backend` действует один серверный голосовой профиль по умолчанию для живого контура;
- панель уже умеет хранить много голосовых профилей и привязок;
- но для нескольких роботов с разными одновременными голосами потребуется следующий этап серверной маршрутизации.

## Раздел `Экран и лица`

Должен поддерживать:

- выбор экранной темы;
- выбор стиля отображения;
- выбор семейства лиц;
- набор эмоций по состояниям:
  - ожидание;
  - слушаю;
  - думаю;
  - говорю;
  - ошибка;
  - настройка сети;
- яркость экрана;
- предварительный просмотр.

## Раздел `Пробуждение`

Должен поддерживать:

- имя пробуждения:
  - базовая цель: `Гоша`
- отображаемое имя пробуждения;
- включение и выключение распознавания;
- выбор режима:
  - без пробуждения;
  - стандартное пробуждение;
  - пользовательское пробуждение;
- чувствительность;
- поведение в режиме прослушивания.

## Раздел `Память`

Должен поддерживать:

- тип памяти;
- кратковременную память;
- очистку памяти;
- память по говорящему;
- статус наличия данных;
- безопасный просмотр без раскрытия секретов.

## Раздел `Инструменты MCP`

Должен поддерживать:

- список официальных сервисов;
- список пользовательских сервисов;
- включение и выключение инструментов;
- получение конечной точки `MCP`;
- отображение итогового набора инструментов для выбранного робота.

## Раздел `База знаний`

Должен поддерживать:

- выбор профиля базы знаний;
- привязку базы знаний к ассистенту;
- загрузку документов;
- просмотр подключённых документов;
- статус индексации;
- безопасный журнал обновления.

## Что относится к платформе, а что к прошивке

### На стороне `GOSHA_PLATFORM`

- имя ассистента;
- роль;
- язык диалога;
- голос;
- скорость речи;
- высота голоса;
- память;
- модель;
- `MCP`;
- база знаний;
- привязка профиля к роботу.

### На стороне `GOSHA_FIRMWARE`

- язык локального интерфейса;
- локальные звуковые подсказки;
- имя точки доступа;
- имя настройки по Bluetooth;
- стиль экрана;
- тема экрана;
- яркость;
- набор лиц и эмоций;
- локальное имя пробуждения;
- поведение экрана в автономных состояниях.

## Правило совместимости

Нельзя ломать уже работающий совместимый контур без псевдонимов и переходного периода.

Поэтому:

- `OTA` и `activate` уже можно переводить на `/gosha/...`;
- старые `/xiaozhi/...` надо сохранять как совместимые псевдонимы;
- голосовой путь `WebSocket` пока нельзя резко переименовывать;
- новый путь `/gosha/v1/` допустим только как безопасный псевдоним поверх уже работающего backend.

## Предлагаемая модель хранения

В `GOSHA_PLATFORM` нужно добавить отдельные сущности:

- `assistant_profile`
- `voice_profile`
- `screen_profile`
- `wake_profile`
- `memory_profile`
- `knowledge_profile`
- `mcp_bundle`

Каждая сущность должна храниться отдельно и быть пригодной для масштабирования:

- много роботов;
- много профилей;
- переиспользование одного профиля на нескольких роботах;
- замена поставщика без переписывания внешнего API панели.

## Ближайший этап реализации

1. Сначала реализовать серверную модель данных и API.
2. Затем вывести в панель раздел `Ассистенты`.
3. Потом добавить разделы `Голоса`, `Экран и лица`, `Пробуждение`.
4. После этого связать часть настроек с прошивкой `GOSHA_FIRMWARE`.

## Критерий готовности первой версии

Первая версия считается готовой, когда оператор может из панели:

- выбрать ассистента для робота;
- выбрать голос;
- выбрать язык;
- выбрать экранный профиль;
- выбрать имя пробуждения;
- включить и выключить `MCP`-сервисы;
- привязать всё это к конкретному роботу без перепрошивки, если настройка относится к серверу;
- и отдельно увидеть, какие настройки требуют прошивки или нового OTA-профиля.
