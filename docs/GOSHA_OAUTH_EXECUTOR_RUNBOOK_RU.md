# GOSHA OAUTH EXECUTOR RUNBOOK

Этот документ описывает локальный исполнительный сервис `Codex`, который автоматически вносит правки в ветку `Pull Request`.

## Что это за сервис

Сервис работает отдельно от проверяющего сервиса и выполняет другую роль:

- проверяющий сервис читает `Pull Request` и пишет замечания;
- executor читает замечания, делает правки в отдельной рабочей копии, запускает проверку, создаёт коммит и отправляет изменения в head-ветку PR.

## Где лежит код

- сервис:
  - `/home/max/GOSHA_PLATFORM/oauth_executor`
- локальный запуск:
  - `/home/max/GOSHA_PLATFORM/bin/run_local_oauth_executor.sh`

## Как работает цикл

1. GitHub присылает review с замечаниями.
2. Локальный `oauth_executor` принимает ручной запуск через `GitHub OAuth` или автоматический запуск по webhook.
3. Сервис создаёт отдельную рабочую копию через `git worktree` в `local_only/`.
4. Локальный `codex exec` вносит правки в этой рабочей копии.
5. Сервис запускает проверку:
   - по умолчанию `bash bin/ci_validate.sh`
6. Если проверка успешна, сервис:
   - делает коммит;
   - отправляет изменения в head-ветку PR;
   - оставляет верхнеуровневый комментарий в PR.

## Важное разделение ролей

- `oauth_reviewer`:
  - читает PR и публикует замечания
- `oauth_executor`:
  - применяет правки по замечаниям

Это сделано специально, чтобы не смешивать роль проверяющего и роль исполнителя.

## Что нужно в env

Минимум для ручного режима через браузер:

- `OAUTH_EXECUTOR_SESSION_SECRET`
- `OAUTH_EXECUTOR_SESSION_STORE_DIR`
- `OAUTH_EXECUTOR_SESSION_TTL_SECONDS`
- `OAUTH_EXECUTOR_PROTECTED_BRANCHES`
- `GITHUB_OAUTH_CLIENT_ID`
- `GITHUB_OAUTH_CLIENT_SECRET`
- `GITHUB_OAUTH_REDIRECT_URI`
- `GITHUB_OAUTH_SCOPE`
- `OAUTH_EXECUTOR_ALLOWED_REPOS`
- `OAUTH_EXECUTOR_REPO_PATH`
- `OAUTH_EXECUTOR_CODEX_COMMAND`
- `OAUTH_EXECUTOR_OPEN_TERMINAL`
- `OAUTH_EXECUTOR_TERMINAL_COMMAND`
- `OAUTH_EXECUTOR_TERMINAL_RUNTIME_DIR`

Рекомендуемое значение:

- `GITHUB_OAUTH_SCOPE=read:user repo`

Это значение подходит и для публичного, и для приватного репозитория, а также позволяет тому же вошедшему пользователю не только читать PR, но и отправлять изменения в его head-ветку.

Для явной фиксации модели и уровня размышления рекомендуются:

- `OAUTH_EXECUTOR_CODEX_MODEL=gpt-5.4`
- `OAUTH_EXECUTOR_CODEX_REASONING_EFFORT=xhigh`

Для полного автоматического режима без ручного шага дополнительно нужно:

- `GITHUB_EXECUTOR_TOKEN`
- `OAUTH_EXECUTOR_GITHUB_WEBHOOK_SECRET`
- `OAUTH_EXECUTOR_REVIEWER_LOGINS`
- `OAUTH_EXECUTOR_REVERSE_SSH_HOST`
- `OAUTH_EXECUTOR_REVERSE_REMOTE_PORT`

Почему нужен `GITHUB_EXECUTOR_TOKEN`:

- один пользовательский `OAuth`-сеанс недостаточен для полностью автоматического запуска по webhook;
- webhook приходит без сеанса браузера пользователя;
- значит сервису нужен собственный серверный токен, чтобы:
  - прочитать PR;
  - сделать comment;
  - отправить изменения в ветку.

## Рекомендованный токен GitHub

## Локальный запуск

1. Установить зависимости:

```bash
cd /home/max/GOSHA_PLATFORM
python3 -m pip install -r oauth_executor/requirements.txt
```

2. Экспортировать env-переменные по примеру:

- `/home/max/GOSHA_PLATFORM/oauth_executor/.env.example`

3. Запустить сервис:

```bash
cd /home/max/GOSHA_PLATFORM
bash bin/run_local_oauth_executor.sh
```

4. Открыть:

```text
http://127.0.0.1:18912
```

Если нужен постоянный автозапуск на этой машине без ручного запуска из терминала:

```bash
cd /home/max/GOSHA_PLATFORM
bash bin/install_local_oauth_executor_user_services.sh
```

## Проверка готовности

Быстрый `healthz`:

```bash
curl http://127.0.0.1:18912/healthz
```

Ожидаемые поля:

- `github_ready`
  - настроен ли `GitHub OAuth`
- `service_token_ready`
  - есть ли серверный `GitHub` токен для полного автомата
- `webhook_ready`
  - включён ли полный автоматический цикл по webhook
- `codex_ready`
  - виден ли локальный исполняемый файл `codex`

Журналы задач и API списка задач теперь требуют авторизацию через `GitHub OAuth`.

## Ручной режим через браузер

1. Нажать `Войти через GitHub`.
2. Указать:
   - репозиторий
   - номер `Pull Request`
3. Нажать `Запустить исполнителя`.
4. Смотреть задачу исполнения и лог.
5. Если включён `OAUTH_EXECUTOR_OPEN_TERMINAL=true`, вместе с задачей откроется локальное окно терминала с живым выводом `Codex CLI` и `ci_validate`.

На этой же странице теперь есть блок `Последние задачи`:

- он показывает ручные и webhook-задачи;
- webhook-задачи появляются там автоматически;
- по нажатию на строку задачи открывается её подробный журнал и итог.
- список задач и окно `Результат задачи` теперь имеют фиксированную высоту и внутренний скролл, чтобы страница не уходила бесконечно вниз.
- executor теперь может дополнительно открывать локальное окно терминала-наблюдателя:
  - в нём виден точный вызов `codex exec`;
  - туда же идёт живой вывод правок и команды проверки;
  - окно остаётся открытым после завершения задачи, чтобы оператор видел итог.
- executor теперь отдельно показывает:
  - текущий этап;
  - прошедшее время;
  - давность последнего обновления;
  - явную пометку о возможном зависании, если задача долго молчит.

## Защита от лишних автопрогонов

В текущей версии executor больше не должен уходить в бесконечный цикл по одному и тому же PR:

- повторный webhook по уже обработанному review того же проверенного коммита от того же логина теперь отсекается;
- если `start_webhook_job()` падает до фактической постановки задачи, executor откатывает метку уже обработанного review и не расходует слот автопрогона, поэтому redelivery того же события можно принять повторно;
- число автоматических прогонов по одному PR ограничено параметрами:
  - `OAUTH_EXECUTOR_MAX_AUTO_RUNS_PER_PR`
  - `OAUTH_EXECUTOR_AUTO_RUN_WINDOW_SECONDS`
- шумные внутренние предупреждения `Codex CLI` по плагинам и иконкам теперь скрыты из журнала executor.

## Автоматический режим по webhook

Текущая версия слушает:

- `POST /webhooks/github`

Постоянный внешний путь для GitHub теперь такой:

- `http://151.241.228.232:18876/hooks/oauth-executor/github`

Как это устроено:

- локальный executor слушает `127.0.0.1:18912`;
- локальная user-служба держит обратный SSH-туннель до сервера;
- на сервере панель `Гоша` проксирует webhook в `127.0.0.1:18919`;
- маршрут проверки для оператора:
  - `GET /api/operator/oauth-executor/healthz`

Условия автоматического запуска:

- событие `pull_request_review`
- действие `submitted`
- автор review входит в `OAUTH_EXECUTOR_REVIEWER_LOGINS`
- состояние review:
  - `commented`
  - или `changes_requested`
- если `COMMENTED` review содержит только чистый итог вида `Критичных P0/P1 замечаний не найдено` и у этого review нет inline-комментариев, webhook не запускает executor
- если у такого review есть inline-комментарии по строкам, executor всё равно запускается и берёт в prompt только эти реальные замечания

Важно:

- текущая версия поддерживает только PR из того же репозитория;
- PR из форка пока не поддерживается автоматически.

## Где лежат рабочие копии

По умолчанию:

- `/home/max/GOSHA_PLATFORM/local_only/oauth_executor_worktrees`

Сервис специально не правит основной рабочий каталог напрямую.

## Что делает локальный Codex

В рабочей копии `codex exec` получает:

- данные PR;
- review-замечания;
- только review-сводки от разрешённых логинов проверяющих;
- только inline-комментарии по строкам, связанные с выбранным review;
- правила из `AGENTS.md`.

Верхнеуровневые issue-комментарии теперь сознательно не попадают в prompt executor, чтобы не расширять область автоматической правки случайными или посторонними комментариями.
При ручном повторном прогоне без webhook executor дополнительно сверяет последнее review каждого разрешённого проверяющего по всем состояниям.
Если тот же проверяющий уже позже оставил `APPROVED` или другое неисполняемое review, более старые `CHANGES_REQUESTED` и их inline-комментарии в prompt больше не возвращаются.

После работы он должен:

- изменить код;
- записать короткое сообщение коммита;
- записать краткое резюме правок;
- не делать коммит и не делать отправку изменений сам.

Коммит и отправка изменений делаются сервисом отдельно, чтобы цикл был воспроизводимее.

## Что уже делает текущая версия надёжнее

- не запускает вторую активную задачу для того же `Pull Request`, если первая ещё в очереди или уже работает;
- перед повторным прогоном очищает отдельную рабочую копию до состояния `origin/<head-ветка>`;
- убирает из следующего входа собственные служебные комментарии исполнителя, чтобы агент не спорил сам с собой;
- честно показывает в `healthz`, найден ли локальный исполняемый файл `codex`.
- не должен отправлять в git служебные файлы `.codex_executor_*`:
  - итоговое сообщение `Codex` теперь удаляется до коммита;
  - служебные файлы исполнителя дополнительно внесены в `.gitignore`
- GitHub OAuth-токены больше не живут внутри client-side cookie:
  - cookie хранит только идентификатор серверного сеанса;
  - сам токен лежит в `OAUTH_EXECUTOR_SESSION_STORE_DIR`
- сервисный `GitHub` токен больше не попадает в аргументы процесса `git` при отправке изменений:
  - `git push` теперь идёт через обычный `https://github.com/<repo>.git`;
  - токен подаётся во временный `GIT_ASKPASS`, а не в URL командной строки
- browser cookie executor теперь имеет отдельное имя:
  - `gosha_oauth_executor_session`
  - это убирает конфликт локальных сеансов reviewer и executor на одном `127.0.0.1`
- список задач и детальные журналы больше не читаются без авторизации
- постоянный внешний путь webhook больше не зависит от домена `localhost.run`
- executor отказывается отправлять изменения в защищённые ветки из `OAUTH_EXECUTOR_PROTECTED_BRANCHES`, а также в ветку по умолчанию и базовую ветку PR
- чистый `COMMENTED` review без inline-комментариев больше не тратит запуск executor:
  - webhook пропускает такой review без создания задачи;
  - даже при ручном запуске такой верхнеуровневый итог не попадает в prompt как замечание к правке
- ручной повторный прогон больше не поднимает устаревшие замечания после более позднего `APPROVED` от того же проверяющего:
  - executor сначала смотрит последнее review проверяющего по всем состояниям;
  - если замечания уже сняты более новым review, старые inline-комментарии не возвращаются в prompt
- если локальный `Codex CLI` зависнет без новой строки вывода или перестанет вовремя принимать большой prompt, executor и связанный helper reviewer больше не ждут бесконечно:
  - stdout читается отдельным потоком;
  - запись prompt в stdin вынесена в отдельный поток и попадает под тот же таймаут;
  - по настроенному таймауту процесс принудительно останавливается;
  - задача не должна навсегда зависать в состоянии `running`
- тот же настроенный таймаут теперь ограничивает и шаг `OAUTH_EXECUTOR_VALIDATE_COMMAND`:
  - зависшая проверка больше не держит задачу в `running` бесконечно;
  - при превышении лимита executor завершает задачу ошибкой и освобождает повторный прогон того же `Pull Request`
- для общей быстрой проверки контура на машине можно использовать:

```bash
bash /home/max/GOSHA_PLATFORM/bin/check_oauth_agents.sh
```

## Ограничения текущей версии

- нет автоматического merge;
- нет поддержки PR из fork-репозитория;
- нет автоматического разрешения конфликтов при параллельной отправке изменений в ту же ветку;
- если проверка `ci_validate.sh` падает, сервис останавливается и пишет ошибку в лог и в комментарий PR.
- если локальная user-служба обратного SSH-туннеля остановлена, серверный публичный webhook-адрес перестанет доходить до executor до восстановления туннеля.

## Безопасность

- не логировать токены и секреты;
- держать `GITHUB_EXECUTOR_TOKEN` только во внешнем env-хранилище;
- при `git push` не передавать токен в URL или другие аргументы процесса;
- не использовать основной рабочий каталог как место правок исполнителя;
- не давать сервису права на merge, если это не требуется отдельно.
- не передавать в prompt executor произвольные верхнеуровневые issue-комментарии.
