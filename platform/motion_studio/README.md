## Полный редактор: установленный Live и диагностика v3

В 3D руки ограничены 70° вверх и 55° вниз: левая [-55,+70], правая [-70,+55].
Ноги ±35°, стопы ±30°. Старые библиотечные позы и версии с большим опусканием
адаптируются; точный исходный JSON сохраняется один раз отдельно и доступен

Продолжение 10 сентября добавило безопасный черновик и программную запись
пакета робота. Кнопка **Пакет робота** использует только свежий ответ Live
`capabilities` режима `motion_editor` с текущим набором подключённых приводов,
проверяет каждый кадр по фактическим `joint_limits`, недоступным суставам и
скорости, затем скачивает `.robot-package-draft.json` либо показывает первую
точную причину отказа. Кнопка **Записать в робота** отправляет тот же
проверенный payload через `package_upload_begin/chunk/finish`, затем выполняет
`package_load`, `package_prepare`, `package_sample(0)` и короткую software-run
цепочку `package_run_start/status/stop`: робот подтверждает metadata, первый
кадр активных суставов, owner-bound `run_session_id` и
`hardware_apply:false`. Это не запускает движение сервами и ещё не является
полной постоянной библиотекой робота.
Кнопка **Проверить в роботе** выполняет ту же цепочку readback + software-run
для уже сохранённого active payload из storage, без повторного upload; это
проверка постоянного хранения после переподключения, не аппаратное исполнение.
Кнопка **Удалить в роботе** после подтверждения отправляет только
`package_delete` с ключом доступа и очищает сохранённый active payload без
ARM/POSE и без запуска движения.
Кнопка **Удалить выбранный** в Live-блоке появляется только при
`package_features.delete_by_id:true` и отправляет `package_delete` с
`package_id`, после чего перечитывает `package_list`; текущая установленная
прошивка `motion-targeted-delete-build-20260913-1` эту capability объявляет,
а аппаратный storage-path targeted delete уже принят.
В Live-панели блок **Пакет в роботе** читает статус через `package_list` без
ключа доступа: показывает пустой store или список сохранённых пакетов с
metadata (`name`, длительность, interpolation, число кадров/активных суставов,
`package_id`, размер, CRC32, active-флаг и совпадение калибровки). Действие
**Сделать активным** отправляет только `package_select` с ключом доступа.
Это чтение/выбор active payload без upload, ARM, POSE или run.
В Firmware уже есть host-проверенный package upload protocol
(`package_upload_begin/chunk/finish/abort`, `package_list`, `package_load`,
`package_select`, `package_prepare`, `package_sample`, `package_delete`),
с owner-bound session, access key на finish и запретом package-операций при
ARMED Live-сессии. Adapter подключён к NVS-backed storage backend и может
сохранять payload пакета в namespace `motion_pkg`; player-слой умеет безопасно
подготовить и программно семплировать сохранённый payload без hardware apply,
а software runner `package_run_start/status/stop` проверяет owner-bound
run-сессию, первый кадр 0° и STOP/finish без вызова серв. Hardware runner
`package_hardware_run_start/status/stop` принят на реальном роботе; кнопка
**Запустить в роботе** использует его для выбранного active payload.
Свежие программные проверки: `npm test` 110/110 PASS,
`npm run test:bridge` 16/16 PASS, `npm run build` PASS.


Локальный редактор движений: настоящая модель Гоши, шесть суставов, позы на
временной шкале, воспроизведение в 3D и сохраняемая библиотека. Модуль
изолирован от серверных маршрутов платформы и прошивки.

Вкладка **Live** служит для локального подключения к реальному роботу. Клиент
готовит отдельную сессию настройки. Последняя подтверждённая прошивка на
роботе — `motion-targeted-delete-build-20260913-1`; она объявляет профиль
`motion_editor`, правую руку [-70,+45], ноги ±35° и стопы ±30°, поддерживает
постоянные пакеты с hardware runner и targeted delete по `package_id`. Для
каждого робота нужны совместимая прошивка, проверенный профиль приводов и
аппаратный допуск.
Подробный контракт — [LIVE_PROTOCOL.md](LIVE_PROTOCOL.md).

Live можно подключать по Wi-Fi или через USB. USB работает через локальную
службу на этом компьютере, без зависимости от WebSerial в браузере. Служба
показывает только устройства `303a:1001`, открывает выбранный serial-порт
только после нажатия **Подключить по USB** и передаёт тот же JSON-протокол
Live в строках `@GOSHA-LIVE:<json>`.

В Live сохраняются все шесть ползунков справа. Доступные суставы управляют
роботом по выбранной цели после явного ARM, остальные заблокированы. Числовое
поле показывает команду, бегунок — цель. Слева находятся подключение, ARM,
STOP и свёрнутый пошаговый тест. Переключение на **3D** возвращает обычное
редактирование поз; Live-перетаскивание библиотеку автоматически не меняет.
Значение «Команда» не является измерением реального положения привода.


## Запуск

Нужны Node.js **22.12+** (проверено на 22.15.0), npm и браузер с WebGL2.
Команды выполняются из этой папки. Сначала установите зависимости:

```bash
npm ci
```

Подготовьте модель из шести исходных STL. Скрипту нужны Python 3.10+ и NumPy:

```bash
python3 scripts/prepare_model.py \
  --source-dir '<папка Robot с исходными STL>' \
  --output local_only/public/models/gosha.glb
```

После подготовки:

```bash
bash start.sh
```

Откройте **http://127.0.0.1:5176/**. Редактор слушает только этот компьютер.
`start.sh` также запускает локальную службу USB на `127.0.0.1:5177`.
Зависимости службы (`aiohttp`, `pyserial`) ставятся в
`local_only/usb_bridge_venv` и не меняют системный Python.
Остановка — `Ctrl+C` в терминале сервера. Для разработки: `npm run dev`.
Не запускайте два сервера на одном порту. Повторный запуск использует тот же
адрес и сохраняет доступ к локальной библиотеке браузера.
После установки зависимостей и подготовки модели интернет для работы не нужен.

В Linux с пользовательским systemd можно оставить редактор работать после
закрытия терминала или завершения чата:

```bash
bash start.sh --background
bash start.sh --status
# Остановить локальный сервер редактора и службу USB:
bash start.sh --stop
```

Фоновый запуск использует тот же адрес и библиотеку. Повторный запуск не
создаёт второй сервер; служба из другой рабочей папки не заменяется.
Служба действует в текущем пользовательском сеансе, не включается при загрузке
системы и сама не подключается к роботу. Остановка сервера не является
командой STOP для робота: открытую Live-сессию сначала завершите в интерфейсе.
Остановка фоновой службы завершает и редактор, и локальную службу USB.

## Как создать движение

1. Нажмите **Новое движение** и задайте имя над моделью.
2. Настройте нулевую позу ползунками. Изменение угла автоматически записывает
   всю позу на текущей отметке времени.
3. Перейдите, например, на **1,00 с** щелчком по шкале или полем «Позиция».
4. Настройте следующую позу. **Обновить позу** также позволяет добавить
   неподвижную позу без изменения углов.
5. Нажмите ▶ или пробел, чтобы посмотреть движение. Есть цикл и скорость
   0,5× / 1× / 2×. Пробел не перехватывается при вводе текста.
6. Сохраните отдельный файл кнопкой **Экспорт JSON**.

На модели можно выбирать движущуюся деталь щелчком. «Слева/справа» означает
стороны **экрана в виде спереди**, а не подтверждённую нумерацию приводов.
Доступны нулевая поза, зеркальное отражение, плавная/линейная интерполяция
или удержание позы. Ctrl+Z и Ctrl+Shift+Z отменяют/повторяют изменения
текущего движения. Удаление движения требует подтверждения внутри приложения;
оно не входит в историю отмены.

## Сохранение

- Изменения автоматически сохраняются в `localStorage` этого браузера
  для адреса `http://127.0.0.1:5176`. После перезапуска браузера они остаются.
- **Сохранить версию** создаёт отдельный снимок движения; до 20 версий
  доступны в списке истории. Восстановление можно отменить.
- Экспорт переносит текущее движение со всеми позами. История версий
  хранится только в локальной библиотеке и в экспорт не включена.
- Импорт всегда добавляет отдельную копию, сохраняя существующие движения.
- Другой браузер, другой адрес/порт и очистка данных сайта меняют доступ
  к библиотеке. Для долговременной копии используйте JSON.
- При повреждении библиотеки исходная строка не перезаписывается.
  При недоступном хранилище/нехватке места приложение явно предлагает экспорт.
- До 100 движений, 1000 поз в движении, 120 секунд и 2 МБ на импортируемый файл.

## Что представляет собой экспорт

Файл `.motion.json` содержит версию схемы, профиль модели, относительные углы
в градусах, длительность, способ интерполяции и упорядоченные полные позы.
Первая поза обязательна на 0 мс; вне крайних поз значения удерживаются.
Сохранены `preview_only: true` и `hardware_validated: false`.

Кнопка **Пакет робота** создаёт отдельный черновик
`.robot-package-draft.json` только после Live-подключения к совместимой
прошивке в режиме `motion_editor` с текущими пятью подключёнными суставами:
правой рукой, обеими ногами и обеими стопами. Старые режимы и частичные
`capabilities` отклоняются до создания файла. Черновик включает профиль,
`calibration_id`, активные суставы, пределы, скорость, кадры и флаги
`source_preview_only:true`,
`hardware_validated:false`, `robot_storage_implemented:false`. Левая
отключённая рука исключается, пока она остаётся в нуле; любое её движение
отклоняется. Правая рука +55° допустима в 3D, но отклоняется для текущего
Live-предела +45°. Углы не обрезаются и не масштабируются, а слишком быстрые
участки отклоняются до ручного исправления длительности или поз.

Это **проект для 3D-предпросмотра**. Файл пока нельзя загрузить в прошивку.
Live передаёт временные целевые позы только в отдельно разрешённой сессии;
он не устанавливает движение в постоянную библиотеку робота. Импорт JSON
не открывает Live и не меняет аппаратную калибровку. Команд Home, подстройки
серв, прошивки и установки движений в этом приложении нет.

## Live-настройка

Сначала выберите транспорт. В режиме **USB** кнопка **Найти USB** выполняет
только чтение списка устройств: serial-порт не открывается. В список попадают
только USB-устройства `303a:1001`; локальные пути вида `/dev/...` в интерфейс
не передаются. В режиме **Wi-Fi** используется прежний локальный адрес робота,
например `gosha.local` или адрес домашней сети.

В режиме проверки правой руки (`commissioning_right_arm`) после подключения
может потребоваться отдельное **Включить правую руку**: команда 135° задаёт
начальное удержание. После перезапуска робота это состояние сбрасывается.
Не включайте руку повторно, ориентируясь только на старый журнал: сначала
проверьте текущее состояние и фактическую позу робота.

После включения выберите сустав. Правая рука принимает только фактический
предел из ответа робота: `-5…+5°`, `-15…+15°` или отдельный профиль
`-70…+15°`, если он установлен и объявлен прошивкой.
Ноги/ступни остаются `-1…+1°`, скорость фиксирована на `1°/с`, watchdog —
`300 ms`. Кнопки шага показывают текущий предел сессии; ответ со старым правым
пределом `5°` не разрешает шаг `15°`.

Для плавной ручной настройки откройте сессию и выберите угол **ползунком
сустава** справа. Удерживать мышь или клавишу не нужно: робот плавно идёт к
цели, затем сессия остаётся открытой для следующего угла. Отпускание указателя
и переход между элементами внутри окна не закрывают сессию. Диапазон —
пересечение фактического предела профиля и команды на момент ARM ± допуск
сессии. Для смены сустава нажмите его название справа или кнопку слева. Программа
дождётся STOP предыдущей сессии и выберет новый сустав. Нажмите **Открыть
сессию: имя сустава**, чтобы явно начать управление им. Сам выбор не двигает
робота и не открывает сессию автоматически.
Esc, **СТОП**, потеря окна во время движения, скрытие вкладки и ошибки завершают сессию;
причина остановки остаётся видна после подтверждения робота. В режиме
commissioning_right_arm открытая сессия без движения сохраняется при смене
фокуса окна; keepalive продолжает проверять связь.

Текущая команда и цель отображаются отдельно. **Обновить позу** сохраняет
последнюю подтверждённую команду робота в выбранный кадр только по явному
нажатию; ACK сам не меняет библиотеку движений. Левая отключённая рука
недоступна. Кнопки полной позы/движения в этом режиме недоступны. Пробел не
запускает движение; отпускание пробела завершает сессию. ACK подтверждает
команду; видимое движение подтверждает оператор отдельно.

Для профиля `motion_editor`, допускающего обычное управление позами:

1. Переключитесь в **Live**. Укажите локальное имя или адрес робота и нажмите
   **Подключить по Wi-Fi** либо выберите USB-порт и нажмите
   **Подключить по USB**. До успешной проверки отправляется только запрос
   поддержки Live. Со старой прошивкой появится понятное сообщение об отказе.
2. Для совместимой прошивки будет нужен ключ доступа из отдельно
   подготовленного проверенного профиля. Нажмите **Открыть сессию**.
3. Выберите цель ползунком справа. Для отдельного режима удержания текущей
   позы используйте кнопку **Текущая поза** или пробел; отпускание этого
   вспомогательного управления завершает сессию.
4. Для последовательности используйте воспроизведение только после физической
   приёмки отдельных суставов. Скорость шкалы уменьшается под возможности
   приводов, а автоматического цикла нет.
5. **СТОП** / Esc завершают сеанс. После отпускания и остановки требуется
   явно открыть новую сессию. Потеря окна/связи также прекращает управление.

В Live модель показывает подтверждённые команды приводам. Фактический угол
и наклон отображаются только при наличии соответствующих измерений.
На нынешнем Гоше эти измерения не подтверждены, поэтому баланс нужно будет
оценивать на самом роботе. Автоматического удержания равновесия здесь нет.

Следующий этап: сначала установить и принять стабильную диагностику v2,
затем сверить центры/оси/знаки вращения с конструкцией, сопоставить суставы с
приводами и проверенными аппаратными ограничениями. Только после этого можно
добавлять адаптер записи и отдельную библиотеку движений на стороне прошивки.
Профиль `gosha-preview-v1` находится в `src/motion.js`; все дорожки и органы
настройки строятся по его суставам. Другие модели пока не подключены.

## Модель и проверка

Исходники STL и производный GLB остаются в локальной игнорируемой папке
`local_only/`. Локальные абсолютные пути не входят в код и переносимый контракт.
Скрипт сохраняет 567 818 треугольников, разделяет парные детали по X,
объединяет совпадающие вершины и усредняет нормали. Кнопка BOOT и выключатель
не включены. Координаты остаются в миллиметрах, Z направлена вверх; это
внутреннее соглашение данного просмотрщика, не обычный масштаб glTF в метрах.

```bash
npm test
npm run test:bridge
npm run build
```

Проверяются сохранение/импорт, невалидные файлы, интервалы и интерполяция,
снимки версий, ошибки хранилища, иерархия суставов и чтение настоящего GLB.
`npm run test:bridge` использует подставной serial-порт и локальный HTTP/
WebSocket-клиент; реальное USB-устройство он не открывает.
Проверка настоящего GLB пропускается, если приватная модель ещё не подготовлена.
Браузерные WebMCP-вызовы опциональны: чтение состояния и переход по шкале.
Их контракт проверяется в Node; интеграция с реальным WebMCP браузера
не подтверждена. Прежние браузерные USB-проходы описаны в checkpoint от
8 сентября; свежей браузерной или физической приёмки 10 сентября не было.

Используются Three.js (MIT) и Vite (MIT). Код и интерфейс созданы самостоятельно;
Bottango и другие сторонние редакторы не встроены и не нужны для запуска.


Исторический commissioning-кандидат расширенного хода принимает только явно
опубликованный прошивкой диапазон правой руки `[-70,+15]` при 1°/с и delta
сессии 70°. Он не заменяет текущий `motion_editor` с Live-пределом [-70,+45].
Старые профили ±5/±15 не расширяются, а поддержка в редакторе не означает
установки кандидата или проверки механических пределов.
