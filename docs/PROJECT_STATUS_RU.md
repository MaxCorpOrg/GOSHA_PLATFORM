## На чем остановились

- Базовая связность платформы, Android и прошивки рабочая; первичный полный Android Wi-Fi путь уже пройден.
- Главный блокер выпуска теперь — доказательная повторяемость:
  - Android создаёт локальные WebSocket-пробы из двух периодических контуров;
  - этот поток загрязняет UART и маскирует аудиодиагностику;
  - активный OTA-раздел текущего head прошивки ещё не подтверждён на роботе;
  - нет трёх успешных аппаратных циклов подряд.
- Контракт платформы требует отдельной проверки после TTL 180 секунд:
  - присутствие должно обновиться;
  - либо панель обязана честно показать устаревание;
  - ложный `connected = true` недопустим.
- Известный P1 Android: `Позже` или простое открытие OEM-настроек может навсегда скрыть инструкцию без выбора `Нет ограничений`.
- Известный P2 портала: нужно проверить обычный `form POST` и `XMLHttpRequest`, а не только `fetch`.
- Известный P2 прошивки: диагностика в горячем аудиопути может влиять на измеряемый сценарий и не должна автоматически идти в выпуск.
