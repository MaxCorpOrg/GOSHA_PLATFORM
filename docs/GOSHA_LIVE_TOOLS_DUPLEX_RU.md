# Функции робота и одновременная речь GPT-Live

## Состояние 14 сентября 2026

Владелец уточнил архитектуру: обычный разговор вызывает готовые движения
робота, а Motion Studio отдельно создаёт и загружает их. Требование сначала
произнести «Включи правую руку» отменено. Прежний серверный поток углов
был неверным способом подключения обычных движений.

В ветке `codex/robot-movements-20260914` сервер переходит на именованные
MCP-функции прошивки. Сервер `d7e5e0f` установлен с backup, проверкой старых/новых SHA-256,
перезапуском только голосовой службы и HTTP 200 через основной/промежуточный
адреса. На роботе пока остаётся app `54a0d0e9…d61033`; новый кандидат
`8df041e3…cdf55d` собран, но не установлен. До обновления прошивки новые
функции движения не объявляются, остальные обнаруженные функции сохраняются.
Голос GPT-Live-1, мышление GPT-5.5 medium и Meridian сохраняются.
Владелец подтвердил нормальный разговор; физическая приёмка новых движений
и явная оценка перебивания пока не закрыты.

## Путь функции

1. Сервер проверяет привязку устройства и токен существующего голосового
   соединения. Модель не получает ключ устройства или ключ Motion Live.
2. После голосового `hello` сервер выполняет MCP `initialize` и `tools/list`
   с поддержкой страниц. Операторские функции не запрашиваются.
3. В GPT-5.5 передаётся пересечение списка устройства и серверного списка
   поддерживаемых функций: состояние, аккумулятор, громкость, яркость, тема, каталог движений,
   запуск, статус и остановка.
   Схемы и описания задаёт сервер; произвольные инструменты, URL и команды
   из ответа устройства не становятся доступными модели.
4. Вызовы собираются из вложенных `response.output_item.done`. После
   `response.completed` приложение исполняет функцию, отправляет
   `function_call_output` через `response.item.create`, затем `response.create`.
   Пустое поле `output` в терминальном событии не означает отсутствия вызовов.
5. Устройство возвращает результат по тому же голосовому WebSocket.
   Ожидание выполняется отдельно от приёма микрофона и воспроизведения.

Аргументы проверяются до отправки. Повторные события не повторяют действие.
Отмена разговора убирает ещё не исполненные команды; уже отправленная команда
не считается отменённой физически без ответа устройства. История таких
операций хранится только в памяти и передаётся новой сессии как контекст,
а не как новое поручение. Тайм-аут возвращает `unknown` без автоповтора.
Сбой последовательности событий выключает функции текущей сессии, сохраняя
голосовой разговор. Логи содержат только фиксированные числовые счётчики.

`confirmed` подтверждает получение ответа: значение `false` или `isError`
внутри `device_result` всё равно означает неуспех операции.
Выключение громкости или подсветки не выключает питание робота.
Внешние сервисы MCP, постоянная память и база знаний прежнего движка пока
не подключаются этой реализацией.

## Обычные движения и редактор

Совместимая прошивка предоставляет четыре MCP-функции:

| Серверная функция | Функция робота | Назначение |
|---|---|---|
| `robot_list_movements` | `self.motion.list` | Каталог встроенных и сохранённых движений |
| `robot_play_movement` | `self.motion.play` | Один запуск по `motion_id` |
| `robot_motion_status` | `self.motion.status` | Фактическое состояние исполнения |
| `robot_stop_motion` | `self.motion.stop` | Остановка принадлежащего голосовой сессии запуска |

Сервер передаёт только идентификатор из каталога и собственный уникальный
`request_id`. Модель не задаёт углы, ключ Motion Studio или команды ARM/POSE.
Прошивка проверяет пакет, калибровку и границы; внутри явного запуска готовит
приводы и плавно подводит их к начальной позе. Весь маршрут выполняется
локальным таймером робота, без передачи каждого кадра через облако.

Чтение каталога не включает приводы. Повторная доставка того же запроса
не запускает движение второй раз. `in_progress` подтверждает начало,
`finished` — завершение программного исполнения; физические углы не измеряются.
Остановка удерживает текущую позу. Следующее движение само готовит свою
начальную позу. Закрытие голосового соединения останавливает его запуск;
запоздавшая команда старого соединения не выполняется в новом.

Motion Studio использует прежний редакторский интерфейс с отдельным ключом.
Активное управление или загрузка из редактора исключают обычный запуск,
а обычный запуск исключает управление редактора. Проигрывание сохранённого
пакета по ID не меняет выбранный active-пакет и не пишет NVS.
Загрузка нового пакета через редактор добавляет его в каталог без перепрошивки;
текущий store ограничен двумя слотами.

Первый каталог содержит встроенные «Помахать правой рукой» и «Поздороваться»,
а также совместимые сохранённые пакеты. Старая библиотека Otto целиком не
включена: ходьба, танцы и движения отключённой левой руки требуют переноса
и проверки с текущим аппаратным профилем. Прямые legacy servo sequences,
trim, OTA и операции редактирования голосу не открываются.

`gosha_live_motion.py` остаётся историческим модулем, но маршрутизатор его
больше не импортирует. `GOSHA_VOICE_MOTION_CREDENTIALS` больше не читается;
при обновлении следует убрать эту переменную из окружения службы.

Для длинного движения закрытие по минуте тишины откладывается на ограниченное
время: длительность пакета плюс максимум 30 секунд подготовки. Абсолютный
лимит голосовой сессии 300 секунд сохраняется; он может остановить движение,
начатое близко к этому пределу. Потерянный ответ запуска не вызывает повтор.

## Одновременное слушание и речь

В прошивке с поддержкой серверного подавления эха клиент объявляет
`features.live_duplex:true` и использует двоичный протокол версии 2.
Сервер включает режим только при `GOSHA_VOICE_ENABLE_DUPLEX=1`, доступной
`libspeexdsp1` и этой возможности клиента. Ответ `hello` содержит
`features.live_duplex:true`, `aec:server`. Без согласования остаётся
совместимый попеременный режим.

В согласованном режиме микрофон работает во время Speaking. Сервер
хранит в памяти короткую историю реально отправленного звука после Opus
и сопоставляет её с временными метками воспроизведения от устройства.
При каждом начале ответа сервер сбрасывает декодер образца эха вместе
с декодером воспроизведения робота. SpeexDSP подавляет эхо динамика, после чего микрофон непрерывно поступает
в Live. GPT-Live обрабатывает пересекающуюся речь в текущем разговоре.
На сервере очередь воспроизведения ограничена четырьмя кадрами (240 мс).
Это не полная задержка до динамика: остаются сеть и очереди прошивки.

Синтетическая проверка проверяет ослабление эха более чем на 15 дБ и
сохранение второго сигнала поверх него. Это не результат измерения комнаты,
микрофона или динамика Гоши. После установки нужны проверки собственной
речи без самоперебивания и голоса владельца во время ответа.

## Проверки и установка

`bash bin/ci_validate.sh` включает тесты голоса, MCP, отмены, эха и движения
на имитаторах. Зависимости: Python 3.11+, websockets, libopus0,
libspeexdsp1. `ops/probe_live_tools.py` выполняет короткий платный API-запрос
с имитатором функции; ключ берёт только из окружения. Робот не вызывается.

Серверные файлы устанавливаются с проверкой исходных SHA-256 и резервной
копией. Перезапускается голосовая служба; весь совместимый стек/БД не
перезапускается. Публичный маршрут и relay сохраняются. Для отката
возвращаются файлы и voice-router.env из соответствующей закрытой копии.

Установка прошивки — отдельный этап после сборки, проверки изменений и
актуального аппаратного допуска: резервная копия текущего app, запись только
app-раздела, отдельная сверка, перезапуск, read-only проверка. NVS, assets,
калибровка и store пакетов не должны меняться при установке.
