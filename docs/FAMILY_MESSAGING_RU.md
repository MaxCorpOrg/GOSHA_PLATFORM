## Что реализовано

- Раздел «Семейные сообщения» в карточке робота, отдельный экран `/family?robot=…`.
- Включение режима, выбор «сначала спросить / прочитать сразу», взрослые,
  роли, необязательный телефон, приглашение Telegram, подтверждение и отключение.
- Отправка из панели/приложения в почтовый ящик ребёнка, история 50 сообщений
  и отдельные статусы по каналам. Режим не проверяет тариф или старый флаг `telegram`.
- SQLite с транзакционной записью сообщения и всех заданий доставки.
  Адресаты передаются явно: мама, папа или оба; все активные подключения
  выбранных адресатов получают отдельные задания.
- Telegram: `getUpdates` и `sendMessage`, обработка личных текстовых сообщений,
  одноразовая привязка через `/start`, защита от повторов, отдельный поток
  отправки, чтобы зависшая отправка не задерживала приём.
- API робота для списка адресатов, исходящего сообщения, почтового ящика и квитанций.
  Существующие Device-Id/Bearer проверяются по серверной привязке устройства.
  Переданный в теле чужой robot_id отклоняется; область доступа не выбирает модель.
- Отдельная отключённая по умолчанию служба Telegram и установщик только подготовки.

Android-кандидат: `feature/family-messages-20260929`, от `d1f486b`.
Новый нативный экран открывается прямо из меню приложения. Ключи ботов в
Android не передаются. iOS — отдельный репозиторий, в этом этапе не изменён.

## API v1

Префикс панели: `/api/operator/robots/{robot}/family`.
Префикс приложения: `/api/mobile/robots/{robot}/family`.

| Метод и суффикс | Содержимое / результат |
|---|---|
| GET без суффикса | settings, contacts/channels, messages/deliveries, providers |
| POST `/settings` | enabled (boolean), read_mode (ask / auto) |
| POST `/contacts` | name, role (mother/father/guardian), phone (необязательный E.164) |
| POST `/invite` | contact_id → одноразовая ссылка Telegram на 10 минут |
| POST `/binding` | binding_id, action (approve / revoke) |
| POST `/messages` | contact_id, text, request_id → message_id для ребёнка |

Клиент использует только `X-Mobile-Token`, код первоначальной активации не
даёт доступ к переписке. Операторский доступ закрыт и при отсутствующем
пароле старой панели. POST принимает только JSON до 16 КиБ; проверяется
Origin браузера. Ответы не кэшируются, содержание не записывается в журнал HTTP.
Android отклоняет HTTP вне loopback и перенаправления до передачи токена.
На сервере обращения извне требуют `PANEL_PUBLIC_SCHEME=https`.
Это декларация TLS-терминатора: прямой порт панели нужно закрыть снаружи,
чтобы значение настройки не позволяло обходить HTTPS.

| API устройства | Назначение |
|---|---|
| GET `/gosha/family/contacts` | Разрешённые ID, имя/роль и доступность адресата; без телефонов и токенов |
| POST `/gosha/family/send` | recipients: массив ID, text, request_id |
| GET `/gosha/family/mailbox` | read_mode и входящие id/author/body/expires/state |
| POST `/gosha/family/receipt` | message_id, state: received / spoken |

Почтовый ящик возвращает queued и received до spoken/истечения срока.
Будущий клиент робота обязан сохранять ID принятых сообщений и не озвучивать
повторно при сетевом повторе. received не означает spoken, spoken не доказывает,
что ребёнок услышал. Текст входящего сообщения — данные для отдельного TTS;
его нельзя передавать исполнителю команд или вставлять в системные инструкции.

## Хранение и доставка

База: `$APP_ROOT/family/messages.sqlite3`, каталог 0700, файл 0600.
WAL, foreign_keys, `BEGIN IMMEDIATE`; один бот на базу, один процесс транспорта
защищён файловой блокировкой. Проверяется getMe и сохранённый ID бота.
Ротация токена того же бота допустима; другой бот не наследует привязки.
Повторная привязка создаёт новую запись, не перенаправляет прежние сообщения.

Получатель проходит pending → подтверждение владельцем → active.
Телефон не подтверждает личность. Ссылка хранится только в виде SHA-256,
истекает через 10 минут; новый выпуск отменяет прежнее приглашение.
Отключение отменяет ещё не захваченные задания; уже начатую внешнюю отправку
отозвать гарантированно нельзя. Выключение режима отменяет старую очередь,
которая не оживает после включения.

Состояния доставки: queued → sending → sent / failed / unknown.
`sent` означает только успешный ответ Telegram API. Сетевой обрыв или
незавершённое sending после 120 секунд дают unknown без автоматической
повторной отправки: Telegram sendMessage не предоставляет нашему адаптеру
сквозной ключ идемпотентности. Явные отказы, включая 429, сейчас дают failed;
очередь отложенных повторов для достоверно неисполненных запросов — следующий этап.
Права проверяются при постановке и захвате задания. Входящие события
дедуплицируются до обновления сохранённого offset.

Один текст — до 2000 символов, 30 сообщений в минуту на робота, до 10 взрослых.
Срок доставки — 24 часа; рабочий Telegram-процесс удаляет записи старше 7 дней.
Это технические начальные значения. Для выпуска нужны согласованные сроки,
плановое обслуживание при выключенном боте и политика копий; логическое
удаление строк не обещает физического стирания всех резервных копий.

Если один Telegram-аккаунт подключён к нескольким роботам, ответ на конкретное
исходящее сообщение выбирает нужного робота. Свободное сообщение при
неоднозначности не доставляется. Экран выбора ребёнка и объяснение в боте
ещё нужны до пилота семьи с несколькими детьми. Неподдержанные вложения,
команды, групповые чаты и изменения старого текста сейчас игнорируются.

## Подготовка к установке

Установщик не был запущен на рабочем сервере. Перед будущей установкой:

1. Сверить кандидат с установленными файлами, сохранить копию панели и данных.
   Для Telegram нужен выделенный бот без существующего webhook/другого poller.
2. Развернуть файлы кандидата, HTTPS для семейного API и текущую авторизацию.
   Пока обратный голосовой путь не принят, не включать режим реальной семье.
3. В закрытом файле `runtime/env/family-messages.env` задать:

   ```ini
   GOSHA_FAMILY_TELEGRAM_ENABLED=1
   GOSHA_FAMILY_TELEGRAM_USERNAME=<имя_бота_без_@>
   GOSHA_FAMILY_TELEGRAM_TOKEN_FILE=/opt/gosha_platform/runtime/env/family-telegram.token
   ```

   Токен хранится в указанном файле 0600, вне Git. Имя бота также передать в
   environment панели; токен панели не нужен. Не копировать ключ в APK/HTML.
4. `bash ops/install_server.sh --family-messages-stage` установит только unit
   и перечитает systemd. Эта команда не включает и не запускает бота.
   После готовности каналов транспорт запускается отдельно:
   `systemctl enable --now gosha-family-telegram.service`.
5. Подключить один согласованный аккаунт, проверить оба направления,
   отключение, отсутствие повтора и восстановление после перезапуска.
   Откат транспорта: `systemctl disable --now gosha-family-telegram.service`;
   базу сохранить, откатить панель из копии. Не восстанавливать старые
   активные привязки поверх свежих отзывов доступа.

## Осталось до семейного пилота

- Серверная голосовая функция отправки: из уже аутентифицированной сессии,
  с явным получателем и уточнением неоднозначной фразы.
- Отдельный приём в firmware при закрытом голосовом WebSocket, локальная
  защита от повторного озвучивания, уведомление/вопрос, TTS, квитанция после звука.
- Приёмка этой цепочки на роботе и телефона в реальной сети; TLS устройства.
- Сообщения об ошибках/выбор ребёнка в боте, расписание тишины,
  подтверждение получателем, редактирование и удаление контактов,
  обслуживание хранения и контроль доступности worker.
- MAX, затем WhatsApp: самостоятельные адаптеры и привязки к общей очереди.
- JEV только после сравнения на семейных фразах; сейчас он не участвует в доставке.
