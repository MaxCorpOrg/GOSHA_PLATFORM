# AGENT CHECKPOINT

## Что это за проект

`GOSHA_PLATFORM` — отдельный собственный подготовительный контур для `Гоша`, который больше не должен зависеть от `xiaozhi.me` как от обязательной платформы привязки.

## Как писать новые записи

- Все новые планы, отчёты, объяснения и контрольные точки оформляй русским техническим языком по правилам из `../AGENTS.md`.
- Не используй необъяснённый английский жаргон в обычном тексте.
- Английский оставляй только для команд, путей, имён файлов, веток, коммитов и кода.

## Текущая точка

- Локальная базовая связка панели и шлюза уже существует.
- Папка уже превращена в самостоятельный git-репозиторий.
- Ветка публикации сейчас:
  - `agent/bootstrap-gosha`
- Первая отправка изменений в GitHub уже сделана.
- Короткая каноническая точка входа для следующего агента теперь вынесена в:
  - `docs/NEW_CHAT_CHECKPOINT_RU.md`
- Внешний пользовательский язык проекта переведён на бренд `Гоша`.
- Упоминания `Xiaozhi` оставлены только как внутренний технический слой совместимости, а не как название продукта.
- Для сервера выбран отдельный корень `/opt/gosha_platform`.
- Для подготовительного поднятия выбраны:
  - панель и API: `151.241.228.232:18876`
  - узел `WebSocket`: `151.241.228.232:18080`
- Рабочая копия на сервере в `/opt/gosha_platform/app` уже выровнена с текущим состоянием ветки `agent/bootstrap-gosha`, но развёртывание `backend` сознательно поставлено на паузу из-за большого объёма получения образов и медленного канала.

## Главные ограничения

- Не трогать `/opt/ai_robot` деструктивно.
- Не публиковать `local_only/`.
- Не возвращать жёсткие зависимости на `xiaozhi.me`.

## Ближайший приоритет

- При нормальном канале вернуться к развёртыванию на сервере:
  - завершить получение образа `backend`
  - включить `gosha-backend.service`
  - после этого включить `gosha-panel.service`
  - затем включить `gosha-observer.timer`
