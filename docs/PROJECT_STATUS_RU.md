## На чем остановились

- Развёртывание на сервере остановлено на этапе получения образа совместимого серверного узла `backend`.
- `gosha-backend.service` снят с автозапуска и остановлен, потому что основной образ слишком тяжёлый для текущей скорости канала.
- `gosha-agent-gateway.service` на сервере ещё не поднимался, хотя unit-файл и `env` для него уже подготовлены.
- `gosha-panel.service` и `gosha-observer.timer` тоже не оставлены включёнными, чтобы подготовительный контур не завис в полуподнятом состоянии.
- Совместимые маршруты и внутренние технические идентификаторы пока сознательно не переименовываются, чтобы не ломать интеграцию до отдельного этапа с прошивкой.

## Что делать дальше

- Держать `GOSHA_PLATFORM` как отдельный проект и не тащить туда дерево исходников прошивки `xiaozhi-esp32` до отдельного этапа.
- Когда канал позволит:
  - повторно запустить `bash /opt/gosha_platform/app/ops/install_server.sh`
  - проверить `gosha-agent-gateway.service`
  - дождаться полного получения образов совместимого серверного узла `backend`
  - затем проверить `gosha-backend.service`, `gosha-panel.service`, `gosha-observer.timer`
  - после этого на сервере прогнать:
    - список профилей агентов
    - наследование профиля по умолчанию
    - явную смену активного профиля робота без перепрошивки
- После каждого серверного изменения обновлять эту контрольную точку и серверную рабочую инструкцию.
