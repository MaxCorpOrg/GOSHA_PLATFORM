Клиент принимает правый профиль только с ровно пятью активными суставами:
`arm_positive_x`, четыре ноги/стопы и без `arm_negative_x`. Для правой руки
разрешены только симметричные фактические пределы `-5…+5°` или `-15…+15°`;
`±10°`, предел больше `±15°`, асимметрия, неверная скорость и другой
`watchdog_ms` отклоняются. Ноги и стопы остаются строго `-1…+1°`, скорость всех
активных суставов `1°/с`, `watchdog_ms=300`. `calibration_id` остаётся обязательным
64-hex идентификатором прошивочного профиля и должен соответствовать выбранному
диапазону на стороне прошивки.

Пошаговый UI и проверка исходящих/входящих поз берут размер шага из текущего
`joint_limits`: ответ `capabilities` со старым пределом `±5°` не может
отправить `15°`, а ответ с новым пределом `±15°` показывает и удерживает цель
`±15°`. Отклонение за одну сессию считается от команды на момент ARM по
фактическому пределу этой сессии. Auth, ARM, hold, ACK, STOP, тайм-ауты,
транспорт USB/Wi-Fi и запрет полного воспроизведения в commissioning сохранены.

Проверки: `npm test` — 59/59 PASS, `npm run build` — PASS. Не выполнялись
перезагрузка браузера, подключение к сети, USB или роботу, перезапуск службы,
flash, push, PR и merge.

## USB Live: локальная служба и два транспорта — 2026-09-07

По прямому поручению владельца в `platform/motion_studio/` подготовлен USB-транспорт
для существующего Live без аппаратного запуска. Клиент теперь выбирает
**USB** или **Wi-Fi**: Wi-Fi сохраняет прежний `LiveSession`, а USB подключается
к локальной службе на `127.0.0.1:5177` и не зависит от WebSerial в браузере.
Перечисление USB выполняется только для чтения: в список попадают только устройства `303a:1001`,
пути вида `/dev/...` в UI не передаются, serial-порт не открывается до явного
нажатия **Подключить по USB** и первого Live `hello`.

Локальная служба `bridge/usb_bridge.py` работает через project venv
`local_only/usb_bridge_venv` с `aiohttp` и `pyserial`, слушает только loopback,
принимает точный Origin `http://127.0.0.1:5176` и допускает одного владельца
порта. Serial открывается exclusive на `115200`; DTR/RTS снимаются и
проверяются до открытия, reset/autoresume/replay не выполняются. Кадры USB —
`@GOSHA-LIVE:` + compact JSON `gosha.motion.live.v1` + `\n`; запрос ограничен
4096 байтами, ответ — 16384, очередь — 8 кадров с возрастом кадра. Служба
собирает split-ответы до LF, игнорирует boot logs и различает ошибки
`usb_device_absent`, `usb_port_busy`, `firmware_nohello` и ошибки протокола.
При закрытии WebSocket или serial-ошибке serial закрывается, очереди очищаются,
поздние POSE не досылаются.

`start.sh` теперь управляет обоими локальными процессами: USB-службой и Vite
preview на `127.0.0.1:5176`; Vite запускается напрямую через `vite.js`, чтобы
cleanup владел реальным PID. Фоновый запуск сначала готовит npm build и venv,
а внутренний `--serve` при рестарте не делает повторный `npm ci`/build/install.
`--stop` завершает и редактор, и локальную службу USB; служба из другой рабочей
папки не заменяется.

В интерфейсе пользовательские строки говорят «USB» или «служба USB». Смена
транспорта запрещена при открытой или останавливающейся сессии; список портов
запрашивается с timeout. Ключ доступа вводится как раньше и не сохраняется.
Автоматических init/ARM/POSE нет. Старые ARM, удержание шага, release и STOP
сохранены; STOP остаётся заметным. Отдельная подсказка сообщает, что ACK/STOP
подтверждают принятую команду прошивки, а не измеренный механический угол;
отсутствующие измерения не подменяются расчётом.

Проверки только на программных подставках: `npm test` — 56/56 PASS, `npm run test:bridge` —
10/10 PASS на fake serial/network без железа, `npm run build` — PASS,

## Исправление ползунков Motion Studio — 2026-09-06

Владелец уточнил: ползунок сустава не сдвигается и 3D-модель не меняет позу.
Причина — `selectJoint()` через синхронный Live refresh вызывал
`renderPosition()` и заменял ввод прежним углом до его чтения обработчиком.
Теперь ползунок сохраняет угол в позу до выбора сустава; числовой ввод
сначала проверяется и применяется. Исправление действует в обычном 3D-режиме.

Регрессионные проверки исполняют production-обработчики с синхронным
обновлением панели: все шесть суставов, повторный ввод, запись позы,
числовые углы и ошибочные значения. На прежнем коде все три проверки
